## 1. Executive Summary

동물실 배정 화면의 과도한 로딩은 **루프 내부 반복 SELECT(N+1)** 가 원인이었습니다.  
UI·도메인 규칙은 유지한 채 **데이터 접근 패턴만 재설계**했습니다.

| 지표 | Before | After | 개선 |
|------|--------|-------|------|
| 케이지맵 쿼리 수 (N=50, Cages≈100) | 5,051 | 3 | **99.94% ↓** |
| 목록 화면 쿼리 수 (N=100) | 301 | 4 | **98.67% ↓** |
| 케이지맵 예상 응답 | 50–100초 | 1–2초 | **~25–50×** |
| 목록 예상 응답 | 10–30초 | 0.5–1초 | **~10–30×** |

## 2. Background & Problem

### 2.1 현상
- `ani_control_1.php` 로딩이 과도하게 느림
- 사용자 불만 및 업무 효율 저하

### 2.2 원인
코드 분석 결과 **N+1 쿼리 + 중복 substance 조회**가 주원인.

| Path | Before (per loop) | Cost shape |
|------|-------------------|------------|
| 목록 화면 | row마다 study_2(etc=1) + study_1 + substance | ~3N |
| 케이지맵 | 시험마다 study_1 + 케이지마다 substance | ~N + N×Cages |

**추가 이슈**
- `LIKE` 사용 (와일드카드 없음 → `=` 가 적합)
- `mysqli_real_escape_string` 미적용

## 3. Before — Hot Paths

### 3.1 케이지맵 (`ani_room_allot`)

```php
for ($i = 1; $i <= $sql_row_num; $i++) {
    $data = mysqli_fetch_array($result);
    // 행마다 study_1
    $sql_ex = "select * from study_1 where NO='" . $data['NO'] . "'";
    // 케이지마다 substance (중복 가능)
    $sql_sample = "select st_view from test_substance_tb
                   where substance_name like '$data_ex[sample_name]'";
}
```

**예시** N=50, Cages≈100 → `1 + 50 + 50×100 = 5,051` queries

### 3.2 목록 화면

```php
while ($data = mysqli_fetch_array($result)) {
    // 행마다 3회
    SELECT * FROM study_2 WHERE etc = 1 AND NO=...
    SELECT * FROM study_1 WHERE NO=...
    SELECT st_view FROM test_substance_tb WHERE substance_name=...
}
```

**예시** N=100 → `1 + 100×3 = 301` queries

## 4. After — Method

```text
Collect keys  →  Batch IN queries  →  Build hash maps  →  O(1) render lookup
```

| Cache | Key → Value |
|-------|-------------|
| `study_1_cache` | NO → 시험 메타 |
| `substance_cache` | sample_name → st_view |
| `etc_cache` | NO → 순화(etc=1) rows |

### 4.1 배치 조회 스케치

```php
// 1) NO / sample_name 수집
// 2) 배치
SELECT * FROM study_1 WHERE NO IN (...)
SELECT substance_name, st_view FROM test_substance_tb
  WHERE substance_name IN (...)
SELECT * FROM study_2 WHERE etc = 1 AND NO IN (...)

// 3) 렌더: $study_1_cache[$NO], $substance_cache[$name]
```

### 4.2 기타 개선
- `LIKE` → `=`
- `mysqli_real_escape_string` 적용
- 목록·케이지맵 **Dual hot path** 동일 패턴 적용

## Appendix — Terms

| 용어 | 설명 |
|------|------|
| **N+1** | 1회 조회로 N건을 가져온 뒤, 건마다 추가 쿼리 N회 |
| **Batch (IN)** | `WHERE id IN (...)` 로 한 번에 적재 |
| **In-memory cache** | 조회 결과를 연관배열에 두고 O(1) 재사용 |
